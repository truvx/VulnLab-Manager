# Contributing

Thanks for considering a contribution to VulnLab Manager.

## Before opening an issue
- Search existing issues.
- Include OS and CPU architecture, QEMU version, app version, import format, and concise reproduction steps.
- Redact usernames, private paths, tokens, and sensitive VM metadata from logs.

## Pull requests
- Keep changes focused.
- Explain user-visible behavior and platform-specific impact.
- Run the checks available for your change.
- Do not commit VM images, secrets, generated installers, or machine-specific data.
- Update documentation when commands, networking, or packaging behavior changes.

## Safety
Only test with virtual machines and systems you own or are explicitly authorized to assess. Keep intentionally vulnerable targets on an isolated lab network.
